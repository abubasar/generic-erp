**Tracking with Entity Framework Core
When you query an EntitySet EF persists the state of the records returned and keeps track of any changes that are applied on the records.
It is so that when you call SaveChanges() over the dbContext, all those changes are updated over to the database.
Use AsNoTracking() when you don’t require the entities returned by your query need to be tracked and updated back to database.

Principles of Clean Architecture
The core principles of Clean Architecture include:

Dependency Rule: Dependencies should always flow inwards, from outer layers to inner layers.
Stable Abstractions: Components in higher-level layers should depend on stable abstractions, not on lower-level details.
Single Responsibility Principle: Each component should have a single responsibility.
Open/Closed Principle: Components should be open for extension but closed for modification.
Liskov Substitution Principle: Subtypes should be substitutable for their base types.
Interface Segregation Principle: Clients should not be forced to depend on interfaces they don’t use.
Dependency Inversion Principle: High-level modules should not depend on low-level modules; both should depend on abstractions.


CLEAN ARCHITECTURE:
Core: Contains the application’s business logic, domain models, and interfaces for external dependencies.
Infrastructure: Implements the interfaces defined in the Core layer. Includes database access, external services, and other infrastructure-related code.
Web (or Presentation): Houses the user interface components such as controllers, views, and other web-related code.

EAGER LOADING:
Eager Loading helps you to load all your needed entities at once; i.e., all your child entities will be loaded at single database call. 
This can be achieved, using the Include method, which returs the related entities as a part of the query and a large amount of data is loaded at once.

LAZY LOADING:
It is the default behavior of an Entity Framework, where a child entity is loaded only when it is accessed for the first time. 
It simply delays the loading of the related data, until you ask for it.
***Lazy Loading can lead to the N+1 query problem, where accessing a collection of entities triggers individual queries for each related entity. 
This can cause performance degradation if not carefully managed. Techniques like eager loading or explicit loading can be used to mitigate this issue.

EXPLICIT LOADING:
There are options to disable Lazy Loading in an Entity Framework. After turning Lazy Loading off, you can still load the entities 
by explicitly calling the Load method for the related entities. There are two ways to use Load method



// Inefficient way

for (int i = 0; i < 1000000; i++)
{
    result += i.ToString();
}

// Better way
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000000; i++)
{
    sb.Append(i.ToString());
}
string result = sb.ToString();
The first implementation uses the += operator inside a loop to concatenate strings, which can be inefficient 
because it creates a new string object in each iteration, resulting in unnecessary memory allocations and copying. 
The second implementation uses the StringBuilder class, which provides a more efficient way to concatenate strings, 
especially within loops. By using the Append method of StringBuilder to build the string gradually, 
we avoid unnecessary memory overhead and achieve better performance.

                   .OrderBy(item => item.AnotherProperty)
                   .ToList();

// Optimized query

                   .ToList();

However, if ordering is not necessary for the application’s logic, it introduces unnecessary overhead. 
By removing the OrderBy operation from the LINQ query, we optimize the query to perform only the filtering operation, 
resulting in improved performance.

Avoid Boxing and Unboxing

// Boxing example
object boxed = 10; // Boxing occurs here

// Unboxing example
int unboxed = (int)boxed; // Unboxing occurs here
Boxing and unboxing operations involve converting value types to reference types and vice versa, 
which can introduce performance overhead. In the example, the assignment of an integer value 
to an object (boxed) results in boxing, while casting the object back to an integer (unboxed) results in unboxing. 
By minimizing the use of boxing and unboxing operations, we can improve the performance of the application.

Use Structs for Small Data Structures
For small, lightweight data structures, consider using structs instead of classes. Structs are value types and are often more efficient in terms of memory allocation and access.

// Class example
class Point
{
    public int X { get; set; }
    public int Y { get; set; }
}

// Struct example
struct Point
{
    public int X { get; set; }
    public int Y { get; set; }
}
